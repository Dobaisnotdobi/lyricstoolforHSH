# Lyrics Slot Viewer

가사를 슬롯 단위로 관리하고 화면에 표시하는 웹 애플리케이션입니다. 회원가입이나 별도 서버 없이 브라우저에서 사용합니다.

## 주요 기능

- 슬롯 생성·선택·이름 변경·개별 삭제 및 확인 후 전체 삭제
- TXT 업로드와 여러 TXT 파일의 드래그 앤 드롭
- 아티스트·앨범명 검색 또는 Apple Music 앨범 링크로 수록곡과 가사를 조회해 슬롯에 저장
- 슬롯 드래그 정렬, 좌우 방향키로 이전·다음 슬롯 선택
- 읽기·수정 모드 전환, 가사 직접 입력·편집
- 글꼴(Sans/Serif/Mono), 크기, 정렬, 굵기, 글자·배경 색상, 여백, 자간·행간 설정
- 배경 단색·그라데이션 전환, 프리셋 6종, 시작·끝 색상과 방향 직접 설정
- UI 라이트·다크(어두운 회색)·시스템 테마, 상단 버튼으로 빠른 전환
- 사이드바 접기·펼치기, 사용 설명서
- 가사·슬롯 순서·선택 상태·뷰어 설정 자동 저장

## 실행 방법

Node.js 22와 npm을 사용합니다. 저장소 폴더에서 실행하세요.

```sh
npm ci
npm run dev
```

개발 서버: http://localhost:3000/

```sh
npm run lint
npm run build
npm run preview
```

lint는 TypeScript 오류 검사(tsc --noEmit)입니다. 빌드 결과는 dist에 생성됩니다.
미리보기: http://localhost:4173/lyricstoolforHSH/

## 사용 방법

1. 왼쪽 **+** 버튼으로 슬롯을 만들고 목록에서 선택합니다. 슬롯에 마우스를 올리면 이름 수정·삭제 버튼이 나타납니다.
2. **TXT 업로드**로 UTF-8 가사를 불러옵니다. 선택된 슬롯이 있으면 해당 슬롯에 입력하고 기존 내용이 있으면 덮어쓰기를 확인합니다. 선택된 슬롯이 없으면 새 슬롯을 만듭니다.
3. 여러 TXT 파일을 왼쪽 목록에 드롭하면 파일명으로 각각 새 슬롯이 생성됩니다.
4. 슬롯 왼쪽 손잡이를 드래그하여 순서를 바꿉니다. 입력 중이 아닐 때 **← / →** 키로 슬롯을 이동합니다.
5. 상단 모드 버튼으로 읽기·수정 모드를 전환하고 수정 모드에서 가사를 편집합니다.
6. **뷰어 설정**에서 표시 방식을 조절합니다. 가운데 정렬에서는 여백 조절이 비활성화됩니다.
7. **배경 색상 → 그라데이션**에서 라벤더·하늘·민트(밝은 배경)·차콜·숲·자두(어두운 배경) 프리셋을 선택합니다. 프리셋 선택 시 배경에 맞는 글자색도 적용되며 이후 직접 변경할 수 있습니다. **직접 설정**에서 시작·끝 색상과 방향(0~360°)을 조절하거나 색상 순서를 바꿀 수 있습니다. 단색으로 전환하면 이전 단색 배경이 복원되며 그라데이션 설정도 보관됩니다.
8. **뷰어 설정 → UI 테마**에서 라이트·다크·시스템 설정을 선택합니다. 상단 달/해 버튼은 라이트·다크를 직접 전환합니다. 시스템 설정은 운영체제 테마 변경을 따라갑니다. UI 테마는 사이드바·메뉴·설정창·대화상자에 적용되며 가사 색상과 배경은 바꾸지 않습니다. 기존 사용자의 기본 테마는 라이트입니다.

### 앨범 가사 가져오기

PC Chrome에서 벅스를 쓴다면 왼쪽 **가사로딩**를 누르고 **가사로딩** 버튼을 북마크바로 한 번 끌어 놓습니다. [북마크 등록 화면](https://dobaisnotdobi.github.io/lyricstoolforHSH/?setup=bugs)에서도 등록할 수 있습니다. 이후 원하는 벅스 앨범에서 북마크를 누르면 뷰어에 해당 앨범의 수록곡이 표시됩니다. 복사·저장할 권한이 있는 곡을 고르고 **선택한 가사 N곡 가져와 저장**을 누르면 공개된 가사가 곡별 슬롯에 저장됩니다. 가사 미제공·열람 제한 곡은 결과에 표시됩니다.

같은 벅스 앨범을 다시 열면 기존 가사가 있는 슬롯은 건너뜁니다. 최근 Apple Music에서 열어 슬롯에 담은 앨범과 아티스트·앨범·전체 곡 순서가 일치하면 해당 슬롯을 사용합니다. 두 목록에 발매일이나 재생시간이 있으면 이 정보도 대조합니다.

Apple Music과 LRCLIB로 검색하려면 다음 순서를 따릅니다.

1. 왼쪽 **앨범 가사 가져오기**에서 아티스트·앨범명을 검색하거나 Apple Music 앨범 링크를 붙여넣습니다.
2. 검색 결과에서 아티스트와 발매일을 보고 원하는 버전을 선택합니다. 링크를 넣었다면 **앨범 열기**를 누릅니다. 선택한 시점에 Apple 카탈로그에서 수록곡과 순서, 재생시간을 읽고 LRCLIB에서 해당 녹음의 가사를 조회합니다.
3. 확인된 곡 중 원하는 곡을 고른 뒤 **가사 N곡 저장**을 누릅니다. 같은 Apple 발매판을 검색과 링크 중 어느 쪽에서 다시 열어도 같은 슬롯을 찾습니다. 이미 들어 있는 가사는 보존합니다. 가사가 없는 곡은 화면에서 확인할 수 있습니다.

앨범의 영문명을 모를 때는 **검색 기준 → 아티스트별 앨범**에서 가수 이름만 검색한 뒤 발매일과 앨범명을 보고 선택하세요. 한국과 미국 카탈로그에서 같은 앨범·곡 ID로 확인한 제목과 아티스트의 다른 표기가 있으면 함께 표시하고 가사 조회에도 사용합니다. 한글 검색어나 한국 Apple Music 링크로 연 앨범은 확인된 한글 표기를 우선하고, 미국 링크로 다시 열어도 동일한 곡 ID로 슬롯을 찾습니다.

**다른 제목으로 가사 확인**에서는 자동으로 일치하지 않은 곡을 다시 확인할 수 있습니다. 같은 아티스트·앨범에 재생시간이 가까운 다른 언어의 제목이 있으면 양쪽 정보를 보고 **이 곡의 가사 사용**을 누르거나, 알고 있는 곡명을 입력해 **다시 찾기**를 누르세요. 후보를 확인한 뒤에도 실제 슬롯 저장은 **가사 N곡 저장**에서 이루어집니다.

기존 벅스 슬롯은 **벅스 주소**에서 같은 주소를 사용하세요. 《해방》과 《무한궤도》는 기존 예시 목록을 열 수 있습니다. 그 외 벅스 주소는 **앨범 이름으로 검색**으로 전환하거나 벅스의 수록곡 표를 붙여넣은 뒤 **온라인 가사 조회**를 누릅니다. 제목을 한 줄씩 입력할 수도 있습니다.

가사를 함께 가져오려면 **곡별 가사 TXT 선택**에서 사용할 수 있는 UTF-8 가사 파일을 고르세요. 파일 이름을 곡 제목과 맞추면 본문과 줄바꿈이 해당 슬롯에 들어갑니다. 예를 들어 `EASY A.txt`는 **EASY A**에 연결됩니다. 같은 앨범에서 먼저 추가했던 빈 슬롯은 그대로 채우고, 가사가 들어 있는 슬롯은 보존합니다. 가사 파일 없이 제목만 추가하면 슬롯의 본문은 비어 있습니다. 곡 정보 링크로 벅스 원문을 열 수 있습니다.

검색어와 앨범 ID는 Apple 카탈로그로, 가사를 찾기 위한 곡 정보는 LRCLIB로 전송됩니다. 가사는 사용 중인 브라우저에 저장합니다. 지역별 발매판과 가사 DB 등록 여부에 따라 제공 범위가 다릅니다. 파일로 읽은 가사는 외부로 전송하지 않습니다. [Apple Search API](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/) · [LRCLIB API](https://lrclib.net/docs)

## 데이터 저장

브라우저 localStorage에 다음 키로 자동 저장합니다.

| 키 | 저장 내용 |
| --- | --- |
| lyrics-slots | 슬롯 ID, 이름, 가사, 순서, 생성·수정 시각 |
| lyrics-recent-apple-album | 벅스 수록곡과 기존 슬롯을 대조하기 위한 최근 Apple Music 앨범 한 개의 메타데이터 |
| lyrics-selected-slot-id | 선택한 슬롯 ID |
| lyrics-settings | 글꼴, 색상, 정렬 등 뷰어 설정 |
| lyrics-edit-mode | 읽기·수정 모드 |
| lyrics-sidebar-open | 사이드바 열림 상태 |
| lyrics-ui-theme | UI 테마 선택(light/dark/system) |

같은 브라우저 프로필과 같은 출처(프로토콜·호스트·포트)에서는 새로고침·재접속 후에도 유지됩니다. 사이트 업데이트는 저장 데이터를 초기화하지 않습니다. 저장소는 경로별로 분리되지 않으므로 같은 출처에서 동일 키를 쓰는 다른 앱과 충돌할 수 있습니다.

localhost, 기존 호스팅 주소, GitHub Pages는 출처가 달라 데이터가 자동 이전되지 않습니다. 기존 주소의 데이터는 그대로 남습니다. 다른 기기·브라우저와 동기화되지 않으며 사이트 데이터 삭제·비공개 모드 종료 등에 따라 사라질 수 있습니다. 서버 백업이나 내보내기 기능은 없으므로 원본 TXT를 따로 보관하세요. 업로드한 가사는 서버로 전송하지 않습니다.

## 환경변수와 보안

현재 앱에는 GEMINI_API_KEY나 다른 API 키가 필요하지 않습니다. Vite 설정에서 Gemini 키를 브라우저 코드에 주입하지 않습니다. .env, .env.*, 로컬 설정과 일반적인 인증 파일은 .gitignore로 제외합니다. 브라우저에 노출되는 VITE_* 변수에는 비밀값을 넣지 마세요.

기존 패키지의 @google/genai, dotenv, express, better-sqlite3, @types/express는 현재 앱 코드에서 사용하지 않습니다. 이번 배포 설정에서는 의존성과 잠금 파일을 유지했습니다. 실행에 필요한 서버 전용 기능은 없으며 정적 호스팅으로 동작합니다.

## 배포 및 업데이트

1. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다.
2. 저장소에서 Actions 실행을 허용합니다. github-pages 환경에 승인 규칙이 있으면 배포 시 승인합니다.
3. 변경 사항을 main에 push하면 .github/workflows/deploy.yml이 자동 실행됩니다.
4. Node.js 22에서 package-lock.json에 맞춰 npm ci로 설치하고 TypeScript 검사와 npm run build를 실행합니다. 공식 Pages Actions로 dist를 업로드·배포합니다.
5. **Actions → Deploy to GitHub Pages**에서 결과를 확인합니다. 실패한 단계의 로그에 설치·타입 검사·빌드 오류가 표시됩니다.

**Run workflow**에서 main을 선택해 수동 실행할 수도 있습니다. 다른 브랜치의 수동 실행은 배포하지 않습니다. 별도의 API 키나 사용자 토큰 Secret은 필요하지 않습니다.

프로덕션 base path는 /lyricstoolforHSH/이며 개발 서버는 기존 / 경로를 사용합니다. PR 생성만으로 배포되지 않으며 main에 병합하면 자동 배포가 시작됩니다.

